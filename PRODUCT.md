# Product

## Register

product

## Users
The primary user is the author of the tool, using Emingle during real scrolling capture sessions on desktop. The user is actively comparing the current stitched output against what is visible on screen and needs immediate, low-friction feedback while scrolling.

## Product Purpose
Emingle captures a selected screen region, stitches screenshots together as scrolling progresses, and keeps a live preview visible so the user can judge overlap, spot mistakes early, and stop at the right moment. Success means the interface helps the user finish a long stitched capture with minimal guesswork, minimal retries, and minimal UI interference.

## Brand Personality
Useful, direct, restrained. The interface should feel like a precise utility that stays out of the way while still making state and mistakes obvious.

## Anti-references
Anything flashy, decorative, or showy. Avoid debugger-like visual noise, unnecessary motion, loud highlight treatments, and generic dashboard chrome that competes with the stitched image itself.

## Design Principles
1. The stitched image is the product, everything else exists to support reading it.
2. Feedback should reduce uncertainty immediately, especially around overlap, match quality, and what to do next.
3. Controls and status should stay compact and legible so they never dominate the preview.
4. Motion is allowed only when it clarifies state change or spatial relationship.
5. Every visual treatment should help the user decide how far to scroll next.

## Accessibility & Inclusion
No special accessibility requirements were requested for this project. Avoid needless visual noise and preserve readable contrast where practical, but do not let accessibility scaffolding drive the core interface decisions.
